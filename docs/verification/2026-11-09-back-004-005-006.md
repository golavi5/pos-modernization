## 4xx/5xx seen in the network tab

- `GET /products/categories` → 404 on every page that loads the catalog. **Only failure, and the cause of BACK-005's result.**
- `POST /users` → 400 ×2: my test password used `#`, outside the allowed set (`@$!%*?&`). Test-input error; retried and passed.
- Cashier session: `GET /notifications/unread-count` and `/notifications?pageSize=10` → 403 (cashier lacks the role). Outside these specs.

## Findings

1. **BACK-005 (blocking)** — `GET /products/categories` is shadowed by `GET /products/:id`: `ProductsController` is registered before `ProductCategoriesController` in `products.module.ts`, so Nest matches `categories` as an id and returns a not-found 404. The category list can never load, so the form dropdown, POS tabs and the cashier text are all wrong. Not fixed here (verification-only PR).
2. **After an oversell the product cannot be edited** — stock −1 fails the form's `min=0`, so Save does nothing silently (`back-004-10a-edit-save-blocked.png`). Worked around by setting stock to 0 in the same edit. The product list also shows `-1` with an "In stock" badge. Not part of BACK-004's acceptance; flagged as a follow-up.
